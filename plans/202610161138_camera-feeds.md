# Camera feeds: one reader per camera, frames with the camera's pose

**Status:** Done

Implements [specs/camera.md](../specs/camera.md) in full, and the parts of [config.md](../specs/config.md) ("Streams"), [robot.md](../specs/robot.md) (the seam rows and the fake's paced frames), [bridge.md](../specs/bridge.md) (`bridge.cameras`, lifecycle, front door), [naoqi-websocket-server.md](../specs/naoqi-websocket-server.md) (the `Frame` message), [project.md](../specs/project.md) (numpy and Pillow) and [testing.md](../specs/testing.md) (the live camera test) that it set to `Updated`. It delivers the two feeds, their config, both backends, the WebSocket server's `Frame` stream, the fast tests and one live test on the top camera. It leaves out the gaze verb, the capture-time transform and the bottom camera on a sim (the spec's open questions 1–3), and any camera tool on the MCP server (open question 7: deferred).

## Steps

1. **Dependencies.** Add `numpy>=1.26` and `Pillow>=10` to `dependencies` in `pyproject.toml`, `uv lock`, `uv sync --dev`. Nothing imports them eagerly: check with `python -c "import naoqi_bridge, sys; assert 'numpy' not in sys.modules"` (a fast test can pin this).
2. **Config.** In `config.py`, add `CameraResolution`, `CameraStream` (`enabled`, `resolution`, `fps` with `as_bool` / `as_choice` / an integer-in-range reader), `CameraStreams` (`top`, `bottom`) and `StreamSettings.cameras`. Tests: defaults; `streams.cameras.top.resolution` rejects an unknown value; `streams.cameras.bottom.fps` rejects `0`, `31`, `2.5` and `"10"`; unknown keys; a full round trip from JSON.
3. **Seam.** In `robot.py`, add `Camera`, `CameraRead` and the constants, and the three Protocol methods. In `real_robot.py`, implement them: `subscribe_camera` unsubscribes `<name>_0` … `<name>_6` (ignoring the `False`s), then `subscribeCamera(name, index, code, 13, fps)` and keeps the handle in a per-camera dict; `read_camera` does `getImageRemote`, `getTransform(camera_name, 2, True)`, `releaseImage`, returns `None` for a `None` image, else `CameraRead(width, height, bytes(buffer), ts_s + ts_us / 1e6, (left − right, top − bottom), tuple(transform))`; `unsubscribe_camera` unsubscribes and forgets; `close()` unsubscribes the rest. Tests against the stub `qi`: the exact Naoqi calls and arguments, the stale-handle sweep, the `CameraRead` built from a 12-element image list, `RobotConnectionError` when not connected.
4. **Fake.** In `fake_robot.py`: `subscribe_camera` records `(camera, resolution, fps)` and sets up the camera's state; `read_camera` returns the current frame, advancing to a new one (new `naoqi_ts`, new green level) once `camera_period_s` (default `1 / fps`) has elapsed, else the same `CameraRead` object; `None` period freezes it. Deterministic pixels per the spec; `FAKE_CAMERA_TRANSFORMS` measured on a 2.1 sim at Crouch after `rest()` (top: translation `(0.062, −0.011, 0.414)`, bottom: `(0.052, −0.009, 0.369)`, with their rotations; the figures first written here, `0.528` / `0.482` m high, were not a Crouch pose). `unsubscribe_camera` records and clears; `close()` clears. Tests: size follows the resolution, a frame repeats within the period and changes after it, the period override.
5. **The feed.** New `camera.py`: `CameraFrame` (frozen dataclass; `image` property importing numpy lazily, `np.frombuffer(data, np.uint8).reshape(height, width, 3)` with `flags.writeable = False`), `CameraFeed` per the spec: `start(robot, settings)` subscribes off the loop and spawns the task; the task paces on `loop.time()` from its start, reads through `asyncio.to_thread`, publishes on a new `naoqi_ts`, applies the retry / `CAMERA_DOWN_S` rules and the "no new frame" warning; `stop()` cancels the task, publishes `None`, unsubscribes off the loop; `latest()`, `published_count`, `frames()` (ends on `None`), `wait_for`. `frames()` / `wait_for` check enabled and running at the call. Module constants `CAMERA_DOWN_S = 5.0`, read at run time so tests shorten them. Tests: the list in camera.md "`fake` backend support" that concerns the feed, driven through a bridge on the fake with `camera_period_s` shortened.
6. **Bridge.** In `bridge.py`: construct the two feeds (`self._cameras = {"top": CameraFeed("top"), "bottom": CameraFeed("bottom")}`), expose `cameras` as a read-only `Mapping[Camera, CameraFeed]`; in `start()`, after the mic feed, start each enabled feed with its `CameraStream`, pushing its `stop` on the unwind; in `stop()`, stop the feeds before the mic feed. Export from `__init__.py`. Tests: the enabled cameras are subscribed with the configured settings and unsubscribed at `stop()`; a disabled feed's `frames()` raises `BridgeError`; a stopped bridge's raises `NotRunningError`; `latest()` resets to `None`.
7. **WebSocket server.** For each enabled camera, spawn `_stream_frames(camera)` with the other stream tasks: `async for frame in feed.frames()`, encode with `PIL.Image.frombuffer("RGB", (w, h), data, "raw", "BGR", 0, 1).save(buf, "JPEG", quality=80)` in `asyncio.to_thread`, send `Frame` with `camera`, `frameId`, `width`, `height`, `format`, `data` (base64), `cameraTransform`, `fov`. Cancel with the others. Protocol tables in the spec are the reference; `protocolVersion` stays (a new message is an addition). Tests through `ClientSession` on an in-memory connection: one `Frame` per published fake frame, decodable with Pillow to the right size, the right `camera`, 16 floats; nothing sent for a disabled camera; the task ends with the client.
8. **Example files and README.** Add the `cameras` block to the WebSocket example configs (top on at `qvga`, 10 fps; bottom present and off; the MCP files keep no streams), update `examples/configs/README.md` and the README's streams, config and WebSocket sections. Add the `camera.py` row to AGENTS.md's project map and `camera.py` / `tests/test_camera.py` to `specs/camera.md`'s frontmatter.
9. **Live test.** In `tests-e2e/test_live_streams.py`, `@pytest.mark.requires("camera")`: a bridge on `live_config` with `cameras.top` enabled at `qvga`, 10 fps; wait up to 3 s for `latest()`; assert 320×240, `len(data) == 230400`, `frame.image.shape == (240, 320, 3)`, the transform's last row and a camera height between 0.3 and 0.6 m, at least 5 frames over the next second; append the rate to `MEASUREMENTS`. Run `uv run pytest tests-e2e -rs` on the 2.1 sim (images rebuilt with `uv run naoqi-sim fetch-and-build-images 2.1` when outdated) and, if the image is available, on 2.8.
10. **Statuses.** Flip `camera.md` to `Implemented` and `config.md`, `robot.md`, `bridge.md`, `naoqi-websocket-server.md`, `project.md`, `testing.md` back to `Implemented`, in the files and in `specs/_index.md`; update `_overview.md`'s status table and line; mark this plan `Done` here and in `_index.md`.
